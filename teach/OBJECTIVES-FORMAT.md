# OBJECTIVES.md Format

`OBJECTIVES.md` lives at the workspace root. It keeps the current learning target narrow, observable, and protected from scope creep.

Create it lazily when the learner's goal spans more than one chat or when the objective changes during tutoring.

## Template

```md
# Learning Objectives: {topic}

## Active objective
{Current narrow objective. One main target at a time.}

## Success test
{Observable thing the learner should be able to do without notes or with clearly stated tools.}

## Sub-objectives
- [ ] {skill/concept}
- [ ] {skill/concept}
- [ ] {skill/concept}

## Deferred / out of scope
- {Tempting adjacent topic intentionally postponed}

## Objective changes
- {date}: Changed from {old objective} to {new objective} because {reason/evidence}.

## Open questions
- {Question blocking the next teaching decision}
```

## Rules

- Objectives should be behavioural: classify, explain, debug, predict, design, solve, compare, or transfer.
- Avoid vague objectives like "understand X" unless paired with a success test.
- Record objective changes when the learner's mission, constraints, or observed gaps change the path.
- Keep deferred topics explicit so the tutor does not chase novelty.
- Do not mark sub-objectives complete without observed evidence.
