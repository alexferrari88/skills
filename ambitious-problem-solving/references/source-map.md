# Source Map and Critical Interpretation

This file documents provenance for the rules in `ambitious-problem-solving` and explains how human-facing advice in the source material was critically adapted for safe, high-leverage AI agent execution. It is intended for auditing and maintenance, not normal runtime loading.

**Primary source:** Felix Rieseberg, *“How to be more ambitious: A tutorial for humans with models,”* published 13 October 2026 (updated 16 October 2026), https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/

---

## Status Labels

- **Direct** — Explicitly stated in the source article and translated directly into an operational agent rule.
- **Critically adapted** — Grounded in a concept from the source article, but restructured so an AI agent applies it safely and effectively without falling into LLM-specific failure modes (such as hallucination, reward hacking, or persona role-play).
- **Derived safeguard** — Added based on operational experience with coding and research agents to prevent scope hijacking, over-engineering, or unverified claims when increasing ambition.

## Provenance Table

| ID | Skill Rule | Source Passage / Concept | Status & Critical Rationale |
|---|---|---|---|
| **C1** | **Deeper, not bigger** (increase leverage, rigor, or perspective—never word count or architectural bloat) | Depth section prompt: *“I want a deeper version of this task, not a bigger one.”* | **Direct + Derived safeguard.** Made the central governing rule of the skill because LLMs routinely misinterpret “be ambitious” as “write a longer, more complex response.” |
| **C2** | **Calibrate the ambition contract** (Mode A: Prompt/Plan elevation; Mode B: Open-ended execution; Mode C: Deliver bounded request first + offer concrete elevation; stay at Speed for trivial/expressive tasks) | Intro (Speed vs. Altitude/Depth/Range) + Altitude caveats (*“works best if you really are after some ultimate outcome; it works less well for creative endeavors”*) | **Critically adapted + Derived safeguard.** A human reading the blog post chooses when to apply it; an agent needs explicit mode routing so it does not hijack urgent 2-minute tasks with uninvited 30-minute system redesigns. |
| **A1** | **The Altitude Ladder** (L0 Artifact -> L1 Causal sensemaking -> L2 Urgent decisions with for/against -> L3 Continuous replacement system) | Altitude section: Acme Inc. QBR progression (what changed/why -> 3 urgent decisions -> continuous replacement for the quarterly deck) | **Direct.** Structured as a 4-level ladder (`L0`–`L3`) so the agent can select the highest grounded level rather than jumping blindly to `L3`. |
| **A2** | **Backtest on history and run in shadow mode** before replacing a human process | Altitude section: *“show from our own history that it would have caught things sooner, and run it beside the current one for a quarter.”* | **Direct.** Elevated into a mandatory safety gate (`A3` in `altitude-and-autonomy.md`) to prevent premature deletion of working human checkpoints. |
| **A3** | **4-Prerequisite Autonomy Audit** (signal ingestion, version-to-commit mapping, cross-platform reproduction runtime, closed-loop verification) | Altitude section: keeping apps crash-free required fetching crash reports, mapping app version to git commit, and accessing Windows/macOS/Linux machines to reproduce and verify fixes | **Direct + Critically adapted.** Generalized from Rieseberg's crash-free app anecdote into a reusable 4-point environment readiness audit for any human-out-of-the-loop workflow. |
| **D1** | **Ban vocabulary theater; switch instruments and substrates** | Depth section: *“When prompted to act like a professional, models often switch vocabulary without actually switching methods. When Claude reaches for markdown tables, insist on the use of databases and statistical models.”* | **Direct.** Translated into an explicit check requiring executable instruments (SQL/DuckDB, statistical models, profilers, solvers) over prose tables. |
| **D2** | **The 4-part Depth Upgrade** ((1) unasked expert move, (2) rawest substrate, (3) specific methods/tools, (4) outside judge) | Depth section blockquoted prompt | **Direct.** Used both as an internal pre-execution checklist for Mode B/C and as an explicit prompt-upgrading protocol for Mode A. |
| **D3** | **Adversarial assumption testing & predictive discovery on held-out data** | Depth section: *“Challenge what you know... Try to reproduce that from the raw data”* and *“Build a simulation... find the earliest signal of churn... and show it predicts on data it has not seen.”* | **Direct.** Reinforced with an explicit temporal/out-of-sample holdout requirement so agents do not confuse in-sample overfitting with “producing new knowledge.” |
| **D4** | **Order-of-magnitude target reframing (the “200ms test”) coupled with an anti-reward-hacking guardrail** | Depth section: *“Pick unreasonable goals and tell the model that they're very reasonable: You need your website to load in 5s instead of 10s? Ask for 200ms.”* | **Critically adapted.** Telling a human to demand 200ms is a great way to force an LLM out of incrementalism. However, if an agent tells *itself* that an impossible target must be met without an integrity guardrail, agents frequently cheat benchmarks, drop requirements, or hallucinate numbers. The skill preserves the **10x–50x design-space search** while strictly enforcing honest measurement via the outside judge. |
| **D5** | **Mandatory Outside Judge (External Oracle)** | Depth section: *“Do not ask the model to judge itself... insist on outside validation. Ideally that's a tool the model can run to get feedback immediately.”* | **Direct.** Expanded into a domain-specific catalog of external oracles in `references/depth-and-verification.md`. |
| **R1** | **Replace nouns with functional verbs** | Range section: Tom Kelley & Jonathan Littman (*The Art of Innovation*) trick—reframing a QBR deck as *“getting busy people to believe a story about cause and effect, and to decide under uncertainty, in 30 minutes.”* | **Direct.** |
| **R2** | **Assemble the crew by method, never by role-play** (include constructive + adversarial red-team fields like short seller & forensic accountant) | Range section: *“It is easy to accidentally engage in role play, which will make your transcript weirder without improving the actual outcome... Don't ask the model to write like a short seller, ask it to do what a short seller does to research their position.”* | **Direct.** Operationalized via a 3-tuple translation rule (`{core skepticism, concrete method/tool, target failure mode}`) so the agent extracts methodology while banning theatrical persona prose. |
| **S1** | **Action bias, specific hard targets, and low-stakes sandboxes** | Closing section (“We have been here before”): Bandura's self-efficacy, Locke & Latham's specific hard goals (35-year review), Dantzig's homework, Bannister's 4-minute mile, Collison's Fast list, Gallwey's *The Inner Game of Tennis* / Linux “just a hobby” | **Critically adapted.** Psychological anecdotes about human self-efficacy do not help an LLM directly as motivational stories. They are translated into three operational agent behaviors: (1) run cheap prototypes/experiments immediately instead of asking permission to try, (2) convert vague goals into specific falsifiable targets, and (3) use sandboxes/shadow runs (“v0 experiments”) to make ambitious bets safe to fail. |
